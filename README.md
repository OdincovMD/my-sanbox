# My Sandbox

Изолированная среда разработчика на базе Docker (Ubuntu 22.04) с поддержкой проброса X11 (GUI-приложений) и настроенным виртуальным окружением Python.

## Особенности
- **Безопасность (Non-root user):** Автоматическая синхронизация пользователя хоста с пользователем внутри контейнера (`UID`/`GID`). Теперь все созданные процессы и файлы в примонтированной папке `workspace` будут принадлежать вам, а не `root`.
- **Изоляция:** Раздельная default-сеть (bridge) и жесткие лимиты на потребление ресурсов (2 CPU, 4GB RAM) для защиты хост-машины от зависаний.
- **Оптимизация:** Настроено использование кеша `apt` и `pip` через Docker BuildKit для мгновенной сборки при внесении мелких изменений. Внутреннее Python-окружение вынесено в `/opt/venv`.

## Структура файлов
- `Makefile` - Основной инструмент управления песочницей
- `docker-compose.yml` - Конфигурация запуска сервиса с поддержкой лимитов
- `Dockerfile` - Конфигурация образа (Ubuntu 22.04)
- `packages.list` - Системные пакеты (apt) 
- `requirements.txt` - Библиотеки Python (pip)
- `scripts/` - Стартовые скрипты и утилиты
- `workspace/` - Директория для вашего кода, которая монтируется в `/workspace` внутри контейнера.

## Как использовать
Взаимодействие реализовано через простые команды (в основе которых работает `docker compose`):

```bash
make help     # Показать справку по всем доступным командам
make build    # Собрать образ
make dev      # Запустить интерактивную сессию (создает временный --rm контейнер)
make stop     # Остановить запущенные фоновые контейнеры
make clean    # Полностью очистить образы и локальные тома
```

## GUI Приложения
В песочницу автоматически пробрасывается дисплей X11.
Чтобы запустить сессию с поддержкой графических приложений, используйте:
```bash
make gui
```

## Дополнительно
Если вам требуется увеличить лимиты ОЗУ или отключить сетевую изоляцию, измените аргументы `deploy -> resources -> limits` и `networks` в файле `docker-compose.yml`.
